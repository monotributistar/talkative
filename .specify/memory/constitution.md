# Constitución de Talkative

**Versión:** 1.0.0  
**Ratificada:** 2026-07-24

## I. Identidad transparente

El agente siempre se identifica como asistente digital autorizado. Nunca simula ser el principal, un profesional ni una contraparte.

## II. Soberanía y autoridad mínima

El principal puede revisar, corregir, aprobar, revocar y cancelar. Toda delegación debe estar acotada por caso, acción, datos, contraparte y vigencia. Una autorización nunca se amplía por inferencia.

## III. El modelo no tiene autoridad

El LLM puede proponer texto, intención o planes. Servicios deterministas validan comandos, aplican políticas, ejecutan herramientas y cambian estados.

## IV. Separación de funciones

Quien propone una acción no la aprueba. Quien ejecuta una acción no certifica por sí solo su éxito. El `CaseManager` valida evidencia antes de completar el caso.

## V. Resultado verificable

Un mensaje enviado, una respuesta del modelo o una ejecución sin error no equivalen a trámite completado. Cada tipo de caso define un output contract y evidencia obligatoria.

## VI. Privacidad por minimización

Cada componente recibe sólo los datos imprescindibles. Telemetría y eventos analíticos contienen identificadores y categorías, nunca documentos, nombres completos, fechas de nacimiento ni texto clínico.

## VII. Consentimiento y acciones sensibles

La divulgación de datos exige consentimiento vigente. Pagos, cancelaciones, aceptación contractual, divulgación sensible y acciones irreversibles requieren aprobación humana explícita.

## VIII. Seguridad reforzada para dependientes

La relación con un menor o dependiente debe verificarse. También deben verificarse finalidad, destinatario y alcance antes de compartir sus datos.

## IX. Idempotencia, auditoría y aislamiento

Todo efecto externo usa una clave idempotente. Lecturas, escrituras, descargas y envíos sensibles son auditables. Tenant isolation es obligatorio en cada capa.

## X. Límites médicos

El producto gestiona trámites médico-administrativos. No diagnostica, prescribe ni reemplaza canales de emergencia. Los casos clínicos o urgentes se derivan a una persona o servicio apropiado.

## XI. Desarrollo con datos sintéticos

No se usan datos reales antes de una revisión legal, de privacidad y de proveedores para la jurisdicción del piloto.

## XII. Calidad verificable

Cada cambio incluye casos feliz, límite y fallo. Los contratos públicos se validan automáticamente. Un bug corregido agrega una prueba de regresión.

## Gobierno

- Cambiar esta constitución exige una propuesta explícita, impacto y aprobación del integrador responsable.
- Las specs y tareas deben incluir una verificación de cumplimiento constitucional.
- Excepciones temporales deben documentar alcance, riesgo, responsable y fecha de vencimiento.
