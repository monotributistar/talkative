## Objetivo

Implementar un adaptador determinista y en memoria para buscar y reservar
turnos sintéticos. Debe consumir `TaskCommand`, producir `AdapterResult` y
respetar idempotencia sin decidir el estado del caso.

## Contratos

- Consume: `task-command.schema.json` y `adapter-result.schema.json`.
- Produce: interfaz de adaptador, clínica simulada y evidencia sintética.
- No puede cambiar: contratos T002, Prisma, rutas, `CaseManager` ni conversación.

## Escenarios obligatorios

```gherkin
Scenario: búsqueda con disponibilidad
  Given slots sintéticos para pediatría
  When se ejecuta search_appointment
  Then devuelve succeeded con evidencia availability_options

Scenario: reserva idempotente
  Given un slot disponible y una idempotency key
  When se ejecuta dos veces book_appointment
  Then ambas respuestas tienen la misma referencia
  And existe una sola reserva

Scenario: slot ocupado
  Given un slot ya reservado
  When otra clave intenta reservarlo
  Then devuelve failed con DUPLICATE_REQUEST y retryable false
```
