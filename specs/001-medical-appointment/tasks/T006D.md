# T006D — Baseline y migraciones PostgreSQL

## Objetivo

Convertir la base creada históricamente con `prisma db push` en una base
gestionada por migraciones, preservando sus datos y agregando el dominio del MVP
de turnos médicos antes de comenzar T007.

## Archivos permitidos

- `backend/prisma/**`
- `backend/package.json`
- `docker-compose.yml`
- `.github/workflows/ci.yml`
- `.env.example`
- `.env.compose.example`
- `README.md`
- `specs/001-medical-appointment/tasks.md`
- `specs/001-medical-appointment/tasks/T006D.md`

## Contrato consumido

- Esquema histórico de ocho tablas persistido por `prisma db push`.
- Esquema Prisma aceptado por T003 y T004.

## Contrato producido

- Baseline reproducible para instalaciones nuevas.
- Migración aditiva para las tablas del MVP.
- Procedimiento explícito de adopción para instalaciones históricas.
- Arranque y CI basados en `prisma migrate deploy`.

## Escenarios obligatorios

1. Given una base vacía, when se ejecuta `prisma migrate deploy`, then se crean
   todas las tablas y Prisma no detecta migraciones pendientes.
2. Given una copia de la base histórica sin `_prisma_migrations`, when se marca
   el baseline como aplicado y se despliega, then se agregan únicamente las
   tablas nuevas y se conservan todos los registros históricos.
3. Given el esquema resultante, when se compara con `schema.prisma`, then no
   existe drift.

## Comandos de validación

```bash
pnpm --filter workflow-agent-backend prisma:generate
pnpm --filter workflow-agent-backend prisma:migrate:deploy
pnpm exec prisma migrate status --schema backend/prisma/schema.prisma
pnpm exec prisma migrate diff --from-url "$DATABASE_URL" --to-schema-datamodel backend/prisma/schema.prisma --exit-code
```

## Decisiones que no puede cambiar

- La base histórica original no se modifica durante la validación.
- No se eliminan ni renombran tablas o columnas históricas.
- T007 continúa bloqueada hasta validar los tres escenarios.
