# T007 — CaseManager y máquina de estados

**Owner:** Domain  
**Estado:** done  
**Depende de:** T003, T004, T006D  
**Archivos permitidos:** `backend/src/cases/**`,
`specs/001-medical-appointment/tasks/T007.md`

## Objetivo

Implementar el único componente autorizado a cambiar `Case.status`, con
transiciones deterministas, aislamiento por tenant, control de concurrencia y
una ruta exclusiva de finalización que valide evidencia persistida contra
`MedicalAppointmentCompletion` v1.

## Contratos

- Consume: agregado persistente T003/T004 y
  `medical-appointment-completion.schema.json` de T002.
- Produce:
  - `CaseManager.transition(...)` para transiciones no terminales permitidas.
  - `CaseManager.completeMedicalAppointment(...)` como única ruta a
    `Case.completed`.
  - error tipado para caso inexistente, transición inválida, evidencia inválida
    o actualización concurrente.
- No puede cambiar: contratos T002, schema Prisma, rutas, adaptadores,
  conversación, wiring global ni dependencias.

## Reglas congeladas

1. `transition()` rechaza siempre `toStatus = completed`.
2. `completed` sólo puede alcanzarse desde `executing` o `waiting_external`.
3. `completed`, `cancelled` y `expired` son terminales.
4. Repetir exactamente el estado actual es idempotente y no escribe.
5. Toda lectura y escritura incluye `tenantId`; la escritura usa compare-and-set
   sobre el estado anterior para detectar concurrencia.
6. El reloj es inyectable. Sólo completar establece `completedAt`.
7. La evidencia de finalización debe:
   - respetar estructura, constantes, formatos y propiedades permitidas del
     contrato `MedicalAppointmentCompletion` v1;
   - coincidir con `tenantId`, `caseId` y tipo `medical_appointment`;
   - referenciar un `Attempt` persistido de una tarea `book_appointment` del
     caso con `status=succeeded` y la misma referencia externa;
   - referenciar un `Artifact` persistido, verificado, de tipo
     `appointment_confirmation` y con el mismo checksum;
   - coincidir con la única `CalendarProjection` persistida y su resultado
     `synced` o `failed`;
   - vincular `appointment.confirmation_reference` con la referencia externa
     del intento y `appointment.starts_at` con el inicio de calendario.
8. Repetir `completeMedicalAppointment()` sobre un caso ya completado con la
   misma evidencia persistida es idempotente y no vuelve a escribir.

## Transiciones permitidas

```text
draft -> collecting_information | cancelled
collecting_information -> ready_for_confirmation | needs_user | needs_human | cancelled | expired
ready_for_confirmation -> collecting_information | executing | cancelled | expired
executing -> waiting_external | needs_user | needs_human | blocked | cancelled
waiting_external -> executing | needs_user | needs_human | blocked | cancelled | expired
needs_user -> collecting_information | ready_for_confirmation | executing | cancelled | expired
needs_human -> executing | blocked | cancelled | expired
blocked -> executing | needs_human | cancelled | expired
```

## Escenarios obligatorios

```gherkin
Scenario: transición válida
  Given un caso draft del tenant A
  When CaseManager lo pasa a collecting_information
  Then actualiza status y updatedAt una sola vez

Scenario: transición inválida
  Given un caso draft
  When se intenta pasar directamente a executing o completed
  Then rechaza la operación sin escribir

Scenario: aislamiento y concurrencia
  Given un caso del tenant A o cuyo estado cambió concurrentemente
  When se intenta mutar desde otro tenant o usando el estado obsoleto
  Then no se filtra el caso y no se sobrescribe el cambio

Scenario: finalización verificable
  Given un caso executing con Attempt exitoso, Artifact verificado y una
  CalendarProjection coherente
  When se presenta un MedicalAppointmentCompletion v1 válido
  Then el caso queda completed y completedAt usa el reloj inyectado

Scenario: evidencia incompleta o discordante
  Given que falta evidencia o no coincide con lo persistido
  When se intenta completar
  Then el caso conserva su estado anterior

Scenario: finalización repetida
  Given un caso ya completed con evidencia válida
  When se repite la misma finalización
  Then devuelve el estado existente sin una segunda escritura
```
